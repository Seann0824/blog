飞书文档的编辑器是我用过最顺手的在线文档之一。标题层级、代码块、待办、表格、图的排版都很稳，多人协作也不卡。可惜它没有"发布成个人博客"这个能力——分享链接在手机上打开体验一般，也不能挂自己的域名。

所以这个站点的思路很简单：**写作留在飞书，发布交给流水线。**

## 流水线长什么样

1. 我在飞书知识库里写文档，写完把状态改成公开/移到"已发布"节点
2. GitHub Actions 每小时跑一次 `elog sync`，用飞书 OpenAPI 把文档拉成 Markdown
3. 文档里的图片被下载到本地，链接重写成 `/images/xxx.png`
4. 内容有 diff 就自动提交，Cloudflare Pages 检测到提交后重新构建
5. 你刷新页面，看到的就是新文章

整个过程我不需要打开编辑器，也不需要记命令。

## 几个容易踩的坑

**图片防盗链。**飞书文档里的图片地址带鉴权参数，直接外链到别的站点加载不出来。必须把图片下载下来跟着仓库走，这也是 elog 的图床功能存在的原因。

**文档不是文章。**飞书没有 frontmatter 的概念，标题、日期、标签这些元数据得靠约定。我这里用文档标题当文件名，用 `urlname` 当固定链接，避免改标题就让 URL 失效。

**权限比代码难搞。**飞书自建应用要开 `docx:document:readonly`、`wiki:wiki:readonly`、`drive:drive:readonly` 三个权限，发布版本之后还得把应用加成知识库成员。少这一步，全程 403。

## 为什么不用现成的托管方案

试过几种"飞书一键建站"的服务，问题都一样：主题改不动，数据和域名都不在自己手里，而且按年收费。

现在这套组合里，同步层是 elog（`1.9k` star，还在维护），渲染层是 Astro，内容以纯 Markdown 躺在 Git 仓库里。哪天 elog 不维护了，换掉同步脚本就行，文章一篇都不会丢。

> 写作工具和发布工具解耦，是这个方案最值钱的地方。

## 代码

```bash
# 本地预览
npm run dev

# 从飞书拉一次内容
npm run sync

# 构建静态站
npm run build
```

就这么三条命令。
